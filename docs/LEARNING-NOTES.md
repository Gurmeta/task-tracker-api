# Бележки по ученето (C# и .NET)

Кратки обяснения на понятията, които се срещат във всеки етап.

## Етап 1: solution, API и тестов проект

- **Solution (`.slnx`)** групира проекти. Не съдържа код. `dotnet build` и `dotnet test` работят върху всички проекти наведнъж.
- **Project (`.csproj`)** е един компилируем модул с настройки (версия на .NET, пакети).
- **ProjectReference** позволява на тестовия проект да ползва кода на API проекта.
- **Minimal API**: endpoint-ите се пишат в `Program.cs` с `app.MapGet(...)`, без контролер класове.
- **`record`** е кратък тип за данни (шаблонът го ползва за `WeatherForecast`).

## Етап 2: TaskItem и endpoint-и в паметта

- **`class` и свойства** (`{ get; set; }`): `TaskItem` описва задача. Свойствата са автоматични.
- **`enum`**: `TaskItemStatus` позволява само `Todo`, `InProgress`, `Done`.
- **Nullable reference types**: `string` не може да е `null`, `string?` може. Компилаторът ни предупреждава.
- **Интерфейс** (`ITaskStore`) е договор с методи без код. `InMemoryTaskStore` го изпълнява.
- **Dependency injection**: endpoint-ът казва `(ITaskStore store)`, а .NET му подава реализацията, регистрирана с `AddSingleton`.
- **Singleton**: един екземпляр за цялото приложение. Нужен е, защото списъкът живее в паметта.
- **`lock`**: заявките идват едновременно и `List<T>` не е безопасен за паралелен достъп. `lock` пуска по една нишка в блока.
- **LINQ и лямбда**: `FirstOrDefault(t => t.Id == id)` връща първата съвпадаща задача или `null`.
- **HTTP кодове**: `201 Created` (с `Location` хедър) при създаване, `200 OK` при четене, `404 Not Found` при липсваща задача.
- **`JsonStringEnumConverter`**: показва enum като дума (`"Todo"`), не като число.
- **`public partial class Program;`**: прави класа видим за тестовия проект (ползва се в етап 5).

## Етап 3: пълен CRUD, валидация и HTTP кодове

- **DTO** (`CreateTaskRequest`, `UpdateTaskRequest`): отделни типове за входа. Клиентът не може да подава `Id` или `CreatedAt`. Това предпазва от *over-posting*.
- **`record` с `init`**: свойства, които се задават само при създаване на обекта.
- **DataAnnotations**: атрибути като `[Required]` и `[StringLength(100)]` описват правилата. `Validator.TryValidateObject` ги изпълнява.
- **`TaskItemStatus?` + `[Required]`**: без `?` липсващ статус би станал тихо `Todo` (стойност по подразбиране на enum). С `?` липсата е грешка.
- **`Results.ValidationProblem`**: връща `400` във формат *Problem Details* (стандарт RFC 9457) със списък на грешките по полета.
- **HTTP кодове**: `201` + `Location` (създаване), `200` (четене и промяна), `204 No Content` (успешно изтриване), `400` (невалидни данни), `404` (липсва ресурс).
- **`PUT` е пълна замяна**: клиентът праща всички полета. (`PATCH` е частична промяна, не го правим сега.)
- **`MapGroup("/tasks")`**: общ префикс за група endpoint-и. Кодът е в отделен клас с **extension method** (`this IEndpointRouteBuilder`), за да е `Program.cs` кратък.
- **Неизменяеми обекти в хранилището**: `Update` заменя обекта с нов, вместо да го променя. Така обект, който друга заявка чете, не се променя по средата.
- **Параметри на заявката**: `TaskItemStatus? status` се чете от `?status=Done`. Невалидна стойност дава автоматично `400`.
- **`JsonStringEnumConverter(allowIntegerValues: false)`**: числа като `"status": 1` се отхвърлят.

## Етап 4: SQLite през Entity Framework Core

- **ORM** (Entity Framework Core) превежда C# обекти в SQL таблици и обратно. `DbSet<TaskItem> Tasks` е таблица.
- **`DbContext`** (`AppDbContext`) е "сесия" към базата. Живее кратко: един екземпляр на HTTP заявка (**Scoped** lifetime). Затова `ITaskStore` също е Scoped, не Singleton.
- **Primary constructor**: `class EfTaskStore(AppDbContext db)` е кратък начин да вземеш зависимост и да я ползваш в целия клас.
- **Миграции** са версионирани скриптове за схемата. `dotnet ef migrations add Име` сравнява модела с последния snapshot и генерира `Up` (приложи) и `Down` (върни). Направихме две: `InitialCreate` и `AddDueDate` (виж как добавянето на поле е само `AddColumn`).
- **`dotnet-ef` като локален tool** (`dotnet-tools.json`): версията е закована за проекта, всеки може да я възстанови с `dotnet tool restore`.
- **`Database.Migrate()` при старт**: прилага чакащите миграции. Удобно за малък проект. В екип с няколко инстанции се прави като отделна стъпка в деплоя, за да не се състезават инстанциите.
- **async/await**: заявките към базата са I/O и чакат. `await` освобождава нишката, докато чака, така че сървърът обслужва други заявки. Методите връщат `Task<T>`, а по конвенция имат суфикс `Async`.
- **`CancellationToken`**: ако клиентът прекъсне заявката, токенът се отменя и EF спира заявката към базата. Minimal API го подава автоматично.
- **`AsNoTracking()`**: за четене. EF не следи обектите за промени, което е по-бързо.
- **`ExecuteDeleteAsync`**: изтрива директно с един SQL `DELETE`, без да зарежда обекта.
- **Connection string от конфигурация**: `ConnectionStrings:Default` в `appsettings.json`. Може да се презапише с променлива на средата `ConnectionStrings__Default` (двойно подчертаване), което ще ползваме в Docker. Файловете `*.db` са в `.gitignore`.
- **Value converter**: SQLite не пази часова зона, затова `DateTime` се чете като `Unspecified` и губи `Z`. Конверторът обявява всичко за UTC. Забелязахме го при тест: след рестарт `createdAt` нямаше `Z`.
- **`HasConversion<string>()`**: enum се пази като текст (`"Done"`), не като число.

## Етап 5: xUnit тестове

- **Модулен тест (unit)** проверява малка част изолирано (`RequestValidatorTests`). **Интеграционен тест** пуска истинското приложение и праща HTTP заявки (`TasksApiTests`). Имаме и двата вида, а `EfTaskStoreTests` е между тях: истински EF срещу SQLite в паметта.
- **`[Fact]`** е един тест. **`[Theory]` + `[InlineData]`** е един тест, пуснат с няколко набора данни.
- **Arrange, Act, Assert**: подготви данните, изпълни действието, провери резултата. Всеки тест следва този ред.
- **`WebApplicationFactory<Program>`** стартира API-то в паметта, без реален порт. Ето защо добавихме `public partial class Program;`.
- **Изолация**: xUnit създава нов екземпляр на тестовия клас за всеки тест. Всеки тест получава собствено API и собствен временен SQLite файл (`TaskTrackerFactory`), така че тестовете не си пречат и могат да вървят паралелно.
- **`IDisposable`**: изчиства ресурсите след теста. SQLite пази пул от връзки и заключва файла на Windows, затова викаме `ClearAllPools()`.
- **Тест на миграциите**: `Database.Migrate()` върху празна база доказва, че миграциите се прилагат.
- **Мутационна проверка (ръчно)**: счупих нарочно кода (`DELETE` връща 204 вместо 404) и тестът се провали. Така знаем, че тестовете могат да хванат грешка. Зелен тест, който не може да стане червен, не доказва нищо.
- **Тестване на сурови данни**: за `Z` в датите четем суровия JSON, защото десериализаторът би скрил липсата.
- **`Assert.Equal(["a", "b"], ...)`**: колекция от стойности се сравнява елемент по елемент.
