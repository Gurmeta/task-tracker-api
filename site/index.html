Task Tracker API

A REST API for managing tasks, built with C# and .NET 10. It is a learning project that follows a production-style workflow: tests, containers and CI/CD.

Example request

Create a task, then read it back:

curl -X POST http://localhost:8080/tasks   -H "Content-Type: application/json"   -d '{"title": "Write the docs", "dueDate": "2026-12-01T00:00:00Z"}'

Response, 201 Created:

{
  "id": 1,
  "title": "Write the docs",
  "description": null,
  "status": "Todo",
  "createdAt": "2026-10-19T13:00:00Z",
  "dueDate": "2026-12-01T00:00:00Z"
}

Invalid input returns 400 with the errors listed per field. GET /version reports the running version.

CI/CD

  1. Pull request: build, test, check that EF Core migrations match the model, fail on vulnerable NuGet packages, then build the image and smoke-test the running container (it must not run as root). Nothing is published.
  2. Merge to main: the same checks run again, the image is published to GHCR as latest, and this page is redeployed.
  3. Version tag (v1.0.0): the release workflow checks the tag against the project version, tests, publishes the image as 1.0.0, 1.0 and latest, and creates a GitHub Release with generated notes.

Workflows use minimal permissions and the built-in GITHUB_TOKEN. Third-party actions are pinned to commit SHAs and Dependabot proposes updates weekly.

Run it

The image is published to the GitHub Container Registry by the pipeline. Pin a version such as :1.0.0 for real use:

docker run --rm -p 8080:8080 -v task-tracker-data:/data ghcr.io/gurmeta/task-tracker-api:latest
curl http://localhost:8080/health

Or run from source with the .NET 10 SDK:

dotnet run --project src/TaskTracker.Api

GitHub Pages hosts static files only, so this page describes the API but does not run it.
